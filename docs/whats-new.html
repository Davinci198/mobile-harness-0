Highlights

The five things worth knowing about

If you only read one section, read this one.

mtop, the htop replacement New

htop cannot run in the guest and no distro fixes that, so Mobile Harness ships its own process monitor. Reads /proc directly, standard library Python only, no ps and no /proc/stat.

  • Sort, tree view, zoom, live search, signals, export
  • Simple mode (s) gives a minimal htop-style table
  • Ships with a full README, installed into the guest
  • Fourth quick-command chip in the terminal

Model scanner: latency + working/broken New

Every discovered model gets probed with a real tiny completion, and the result is a three-way verdict you can act on: it works, it is broken, or it timed out — plus the latency it took to answer.

  • Status filter pills: All / Working / Broken / Free
  • Working / Broken / Avg latency summary card
  • Latency badge: green under 2s, amber under 5s, red above or broken
  • Terminal-style live scan log with per-model progress

Settings drawer, edge swipe New

Settings moved out of the tab bar and into an overlaid drawer. Swipe in from the left edge — a 22 dp strip that follows your finger and opens once you pass 32% — or open it from anywhere. Collapsible sections, inline API-key controls, and a connection card that shows what is actually saved.

  • Create Custom API endpoints straight from the connection manager
  • Keyless free providers hide the key field entirely
  • Permission editor stays readable inside the drawer

Plugin APK system New

A real extension surface. Plugins ship as APKs with a manifest contract, talk to the app over IPC, and register their tools into the agent's tool registry.

  • Manifest validation and package management
  • Tools appear to the agent like any built-in tool
  • Settings UI for discovery and enable/disable

On-device Android builds New

Build, install, and launch an APK on the phone itself. No USB, no wireless ADB, no pairing code. The debug APK goes straight to Android's package installer.

  • Build | Health screen with compile-SDK repair
  • Live build progress panel with stage tracking
  • Uninstall via Shizuku or PackageInstaller
  • Logcat tab, once READ_LOGS is granted

Kilo Free, keyless New

A sixth provider tier that needs no account and no key. Kilo's free pool rejects every Authorization header, so Mobile Harness strips it and keeps a loopback proxy alive between turns.

  • Works across Claude Code, DSH, and the other agents
  • Only free-tier model IDs are shown, not the paid catalog
  • Health probe reports "connected without a key"

47 bundled skills New

A curated set of agent skills now ships inside the APK and installs into each agent's own guest skill root, so every agent sees the same library.

  • Per-agent guest roots, with reinstall if one vanishes
  • Completion and failure sections parsed from skill files
  • Risk labels translated in the i18n catalog

Risk-graded approvals Improved

Tool calls are now graded by risk before they run. Approvals show a masked card, and a temporary approval stays sticky until the workflow step actually completes.

  • Offline workflow replay through the same permission gate
  • Masked approval card for sensitive arguments
  • Mid-turn prompt injection while an agent is running

Model scanner

Which models actually answer, and how fast

Discovery and health are two different things. Discovery lists what an endpoint claims to serve; the scanner proves which of those models actually answer a completion, and how long they take.

Five verdicts per model New

Each probe returns a status, the measured latency, the HTTP code, and an optional detail line. Anything other than OK counts as broken.

  • OK — answered a real completion
  • FAIL — refused or not in the live catalog
  • TIMEOUT — no answer inside the probe window
  • ERROR — transport or protocol failure
  • INSUFFICIENT_CREDITS — key works, wallet does not

Scan survives a rediscovery Improved

Re-listing a provider does not throw away what the last scan learned. Prior latency, HTTP code, and health carry over to any model ID that still exists, so a refresh does not reset every badge to grey.

Kind to free tiers Improved

The free pools get gentler treatment, because probing them carelessly burns shared quota that live agent turns need.

  • Probes run two at a time on a free tier, not five
  • No 429 retries there — the retry window is minutes long
  • Paid models on a guest endpoint are recorded as not served, never probed
  • An all-401 batch is treated as an expired token, not a dead catalog

Providers that cannot be probed Improved

Two gateways block completion probes on purpose. Rather than paint the whole catalog red, health there means "listed in the live catalog".

  • OpenCode Zen gates probes to its own client
  • Nous free tier without a guest token falls back to the catalog
  • A failed catalog fetch reports nothing, not everything broken

Read the results at a glance New

A three-up summary card counts working and broken models and averages the probe latency. Filter pills narrow the list to what you care about, and autoscan can re-run the whole thing when you open the list.

  • Pills: All / Working / Broken / Free, plus an autoscan toggle
  • Latency label formatted per model, e.g. 1.4s
  • Terminal-style live log, colour-coded per result
Concurrency is capped at five for normal providers and at two for free tiers, under a semaphore that never exceeds ten. Probes use a 12 s connect and 30 s read timeout, so a hung model cannot stall the whole batch.

mtop

Because htop cannot work here

This is not a preference. htop fails inside the guest for reasons no userland change can fix, so the monitor had to be written from scratch.

Why htop fails Constraint

/proc/stat passes DAC but SELinux denies proc_stat to the app's own domain — the AVC denial reports permissive=0, so there is no workaround. On top of that, PRoot binds the host /proc with hidepid=invisible while the fake root carries no capabilities. Two independent blockers, both outside the app's control.

  • Result: htop dies with Cannot open /proc/stat
  • w fails for the same reason
  • No distro, userland, or htop version gets around it

How mtop gets around it New

Instead of the global counters, it reads only what the app UID is actually allowed to see: per-process /proc/PID/stat, status, and IO. That is enough for a real process table, minus the machine-wide CPU total.

  • Zero external dependencies — standard library Python 3 only
  • CPU% is per process and relative to one core (100% = one full core)
  • Installed to /usr/local/bin/mtop in the guest
  • Self-healing marker (2procwatch-3) rewrites it when the script changes

Interactive mode New

A full curses interface, sized to the terminal. Columns slide in progressively on narrow screens, and the command line takes the remaining space without wrapping.

  • Sort by CPU, memory, threads, IO, PID, or name
  • Tree view with └─ indentation, plus subtree zoom
  • Live search across command, name, and PID
  • SIGTERM / SIGKILL with two-key confirmation
  • Sparklines for CPU% and RSS on the selected process

Simple mode: closest to htop New

Press s for a stripped table — PID, CPU%, RAM, and name — with the selected process's full command in the detail pane. Press it again for the full table.

Remote via adb New

mtop --adb monitors a phone's /proc from a computer, and it is also the fourth quick-command chip in the terminal screen.

  • Auto-detects a Shizuku server: reads .mh-shizuku-port, then scans 20000–20006
  • Each candidate gets a 0.5 s TCP probe, so a closed port is skipped instantly
  • Falls back to classic adb when nothing answers
  • One sample costs two adb calls; details come in one more, cached 2 s

Observation tooling New

Beyond watching, it records. Every sample can be exported or logged as JSONL for later analysis.

  • Export a snapshot as JSON or CSV (e)
  • Continuous JSONL log (l) with process rows per sample
  • Config via ~/.procwatchrc (INI), CLI wins over config
  • Copy a process's full command, plus its environ (y / Y)

Reads the weird cases New

On Android there is always something odd in the process list. mtop colours what matters instead of leaving you to guess.

  • Red: above CPU or RSS alert threshold
  • Yellow: zombie  ·  Green: orphan
  • Purple: very long commands, the usual PRoot wrappers
  • Zombie and orphan counters in the summary
Full README ships with it. The app installs README_procwatch.md into the guest alongside the script, so the key map, the JSONL format, the config file, and the Android limitations are readable on the device itself, offline.

Fixes

The unglamorous half

104 fixes in 30 days. These are the ones that changed behaviour you could feel.

Data loss in the file manager Fixed

Cut-and-paste into the same folder could delete the file. The local file system had a canonical-path guard; the SAF path did not. Both are guarded now, and the clipboard clears when you switch storage roots.

Cold boots and warm sessions Fixed

DSH prewarms the open project so the first turn is not a cold boot, and the warm SDK channel survives token rotations and provider overloads. Transient overloads retry with backoff instead of failing the turn.

Hermes credentials Fixed

The NVIDIA credential is now published on the proxy path, and Hermes' own error line is surfaced instead of a generic failure. A missing config.yaml is created on demand, and a corrupted uv cache is cleared.

Memory and ANR guards Fixed

Checkpoint reads are capped and .git is skipped, so cloning a large repository can no longer OOM the app. Stream ANR guards were ported alongside.

Android build state Fixed

The installed state is now truthful, the previous build log survives a skipped Gradle run, and gradlew gets its executable bit. Uninstall works through Shizuku or PackageInstaller.

Model discovery Fixed

/models Discover scans the provider you are browsing, not just the active one, and shows live scan progress instead of hanging on a wedged scan.

Known limits

Still true

PRoot is not a security boundary. It isolates the Linux userspace from other apps through normal Android sandbox permissions, but it is not virtualization and not a hardened jail. Run only projects and dependencies you trust.
Antigravity runs with --dangerously-skip-permissions. The official agent can execute tools without per-call approval. Quotas and service limits still apply; signing in does not mean unlimited usage.
ARM64 Android 9+ only. No x86 builds, no root required, no Termux required — but also no desktop-class CPU, so heavy Gradle builds are slow.
