### P1 — SafFileSystem.copy nu protejează copierea pe aceeași cale
- Locație: `storage/SafFileSystem.kt:187–215`
- Problema: `LocalFileSystem.copy` are guard `canonicalPath == canonicalPath`, dar SAF nu. La CUT în același folder pe SAF, `copy` citește bytes și scrie la aceeași URI (conținut păstrat), apoi `delete(source)` șterge fișierul → pierdere de date.
- Fix: guard în `SafFileSystem.copy` (compară URI sursă/destinație) și/sau în `FsClipboardRules.pasteInto`.

### P2 — `safely()` înghite excepțiile în tăcere
- Locație: `tools/network/NetworkTools.kt`
- Fix: log la nivel debug înainte de swallow.

### P2 — Mutare de stare Compose din thread de background
- Locație: `ui/PocketDevApp.kt` (install() pentru Studio și Hermes Dashboard)
- Fix: wrap în `withContext(Dispatchers.Main)`.

### P2 — `MemoryTools` sincronizare (verificat: deja acoperit)

## 3. Finding Hermes — „no reply for this turn" (raportat pe device, 2026-10-22)

Reproducere pe emulator: agentul Hermes pornește, promptul este trimis (`prompt submitted (1778 chars)`),
dar turnul se încheie în 573 ms cu `failed=true` și mesajul generic
„Hermes returned no reply for this turn. The warm session was dropped".

Cauza reală, din TUI-ul procesului Hermes (output capturat în cache-ul app-ului):
`⚠️  No usable credentials found for provider 'nvidia'. Set NVIDIA_API_KEY.`

Două bug-uri:

1. **P1 — `hermesEnvironmentFor` pierde cheia NVIDIA pe traseul prin proxy.**
   `routesThroughOpenAiProxy()` este `true` pentru `NVIDIA_NIM`, iar ramura proxy punea doar
   `OPENAI_API_KEY`/`OPENAI_BASE_URL` și returna. Hermes însă rezolvă credențialul unui provider
   din variabila lui proprie (`PROVIDER_REGISTRY`: `"nvidia" -> NVIDIA_API_KEY`), nu din perechea
   OpenAI, deci cheia lipsă → `AuthError` înainte de orice request.
   Fix: în ramura proxy, pentru `NVIDIA_NIM` se publică și `NVIDIA_API_KEY` + `NVIDIA_BASE_URL`
   (base URL către proxy, ca TLS-ul exterior să rămână în procesul app-ului).

2. **P2 — eroarea reală a lui Hermes nu ajungea la utilizator.**
   Textul răspunsului vine doar din webhook-ul de hook-uri; o eroare apărută înainte de pornirea
   streamului este randată doar în TUI (`⚠️  linie`) și nu declanșează niciun hook, deci app-ul
   raporta „no reply" în loc de cauza reală.
   Fix: `WarmTurnBoundary` reține ultima linie de eroare randată de Hermes, iar rezultatul turnului
   o folosește ca mesaj de eșec. Linia de status bar (`⚠ ` cu bullet simplu) nu e confundată cu
   o eroare — se diferențiază prin selectorul de variație (U+FE0F).
